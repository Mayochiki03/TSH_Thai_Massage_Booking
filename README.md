# ระบบจองคิวนวดแผนไทย (Thai Massage Booking)

เว็บแอปจองคิวรับบริการนวดแผนไทยของโรงพยาบาล (หมอนวด 1 คน)
ผู้ป่วยจองเองผ่าน **LINE OA** หรือที่ **เครื่อง kiosk หน้าคลินิก** ได้ **e-ticket รหัสจอง 6 ตัว** ไว้เช็กอิน
เจ้าหน้าที่ดูคิวและเช็กอินที่เคาน์เตอร์ หมอนวดบันทึกผลการรักษา และผู้ดูแลตั้งค่าทุกอย่างได้จากหน้าเว็บ

> สถานะ: **v0.3.0 (กำลังพัฒนา)** ใช้งานได้ครบในโหมดทดสอบ (LOCAL) เหลือเชื่อม LINE จริงผ่าน Cloudflare Tunnel — ดู [CHANGELOG](CHANGELOG.md)

## ความสามารถ

**ผู้จอง (LINE)** จองล่วงหน้า 1–2 วัน · จองให้ตัวเองหรือครอบครัว (บันทึก "ใครจอง ให้ใคร") · รองรับคนที่มี HN และบุคคลทั่วไป · e-ticket ส่งเข้าแชท LINE · ยืนยัน/ยกเลิกได้ถึง 2 ชม. ก่อนนัด · เตือนก่อนนัด 2 ชม.

**Kiosk** จองคิว walk-in ด้วยเบอร์โทร (ใช้ข้อมูลเดิมได้, ชื่อแสดงแบบปิดบัง) · เช็กอินด้วยรหัสจอง + เลข 4 ตัวท้ายเบอร์ · กลับหน้าแรกเองเมื่อไม่มีคนใช้

**เคาน์เตอร์** คิวรายวันแบบไทม์ไลน์ · เช็กอินด้วยรหัส/ชื่อ/เบอร์/HN · รับ walk-in · จองแทน · ยกเลิก · ไม่มาตามนัด

**หมอนวด** เรียกคิว → จับเวลา → บันทึกจุดที่นวด/คำแนะนำ → จบการนวด · ดูประวัติครั้งก่อน

**ผู้ดูแล** Dashboard · รอบเวลา (แม่แบบ + ปิด/เปิดรับรายรอบ/ทั้งวัน) · วันหยุด (เตือนถ้ามีคิว → ยกเลิก + แจ้ง LINE) · กฎการจอง · ข้อความแจ้งเตือน · ผู้รับบริการ · ระงับสิทธิ์ · บัญชีผู้ใช้/หมอนวด · การจองทั้งหมด · ประวัติการใช้งาน

**นักพัฒนา** สลับโหมด LOCAL / DEV_TUNNEL / PRODUCTION · ตั้งค่า + ทดสอบ LINE · ผู้ใช้ LINE จำลอง · สั่งรันงานตั้งเวลา · ล้างข้อมูลทดสอบ · ข้อมูลระบบ

**ระบบ** กันจองซ้อนระดับฐานข้อมูล · โควตา 1 คิว/วัน 2 คิว/สัปดาห์ · ตัดสิทธิ์อัตโนมัติเมื่อสาย · ระงับสิทธิ์อัตโนมัติ (ตั้งเกณฑ์ได้) · audit log (PDPA)

## สถาปัตยกรรม

```
              อินเทอร์เน็ต                                  │                LAN โรงพยาบาล
                                                            │
 LINE OA ─► LIFF (มือถือผู้ป่วย) ─► Cloudflare Tunnel ──────┼─► :4000  PUBLIC API   (/api/public)
                                                            │
       เคาน์เตอร์ / ห้องนวด / ผู้ดูแล / เครื่อง kiosk ───────┼─► :4001  INTERNAL API (/api/staff, admin, dev, kiosk)
                                                            │                │
                                                            │             MySQL 8
```

- Backend แยก 2 พอร์ต — API ฝั่งเจ้าหน้าที่ไม่มีอยู่บนพอร์ตที่ออกอินเทอร์เน็ต
- Cloudflare Tunnel: ไม่ต้องเปิดพอร์ตไฟร์วอลล์ และไม่เปิดเผย public IP ของโรงพยาบาล

| ส่วน | ใช้ |
|---|---|
| Frontend | React 19, Vite 6, Tailwind CSS 4, React Router 7, lucide-react, LINE LIFF SDK (โหลดเฉพาะตอนใช้ LINE จริง), ฟอนต์ Anuphan + Sarabun ฝังในเว็บ |
| Backend | Node.js 20+, Express 4, mysql2, zod, bcryptjs, JWT (httpOnly cookie), node-cron |
| Database | MySQL 8.0 (utf8mb4) |

## เริ่มต้นใช้งาน (เครื่อง dev — Windows)

**ต้องมี:** Node.js 20+ · MySQL 8.0 · Git

```powershell
# 1) ฐานข้อมูล (ลบแล้วสร้างใหม่ + ข้อมูลตัวอย่าง — dev เท่านั้น)
cd database
& "C:\Program Files\MySQL\MySQL Server 8.0\bin\mysql.exe" -u root -p -e "source setup_dev.sql"

# 2) Backend
cd ..\backend
npm install
Copy-Item .env.example .env
npm run dev

# 3) Frontend (หน้าต่างใหม่)
cd ..\frontend
npm install
npm run dev
```

> อัปเกรดจาก v0.2 โดยไม่ล้างข้อมูล: `mysql ... -e "source migrations/001_roles_kiosk.sql"` (ในโฟลเดอร์ database)

### ทดสอบหน้าผู้จองในโหมด LOCAL

หน้าผู้จองจะแสดง "ระบบจองคิวออนไลน์ยังไม่เปิดใช้งาน" จนกว่าจะเลือกผู้ใช้จำลอง:
ล็อกอิน `dev` → **นักพัฒนา › ผู้ใช้จำลอง** → กด **เปิดหน้าผู้จอง** ที่ผู้ใช้ที่ต้องการ

## ความปลอดภัย

- รหัสผ่าน bcrypt · session JWT ใน httpOnly cookie · บังคับเปลี่ยนรหัสผ่านครั้งแรก · ล็อกอินผิดเกิน 10 ครั้ง/15 นาทีถูกพัก
- ผู้จองตรวจ LINE ID token ทุก request · kiosk ยืนยันเช็กอินด้วยเลขท้ายเบอร์โทร
- LINE token เข้ารหัส AES-256-GCM · rate limit · helmet · parameterized query · MySQL user สิทธิ์จำกัด
- **ก่อนขึ้น production:** เปลี่ยน `JWT_SECRET`, `APP_SECRET_KEY`, รหัส DB, รหัสบัญชีตั้งต้น และ **ห้ามรัน** `04_dev_sample.sql`
